## Engineering principles

| Principle | How I apply it |
| --- | --- |
| Design for change | Prefer clear boundaries, reusable components, and simple contracts. |
| Build for failure | Think about retries, idempotency, validation, logging, and recovery paths. |
| Make data trustworthy | Use transactions, concurrency control, and explicit ownership of state. |
| Keep learning visible | Turn concepts into small projects, practical notes, and reusable references. |
